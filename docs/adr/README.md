# Architecture Decision Records

Short records of significant technical decisions: the context, the options considered, the decision, and its consequences. They exist to keep the architecture from drifting as the project grows.

- Add a new ADR for any decision that introduces infrastructure, a vendor, a framework, or a data store.
- Number ADRs sequentially. Never edit an accepted ADR's decision; supersede it with a new ADR instead.
- Statuses: `Proposed` → `Accepted` / `Rejected` → (later) `Superseded by ADR-XXXX`.
